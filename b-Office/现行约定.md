# ActionDecoder 现行约定

本项目长期文档只留这一份。写代码和测试里看不出来的取舍、真机才知道的事与已知缺口。条目被推翻就直接改，不留历史。

## 目标

在 CAD/EDA 里用户拾取实体后，光标旁给出 Top-3 下一步指令候选，单键采纳；不理会就静默消失，不拦截原生输入。目标是自己用起来更快，不是写论文。

## 取舍

- 模型只打分，不生成。对一张固定指令表逐条计算 log P(指令描述 | 当前状态)，共享上下文前缀一次预填充、候选批量计算。不读首 token：指令名多 token、首 token 会撞，零样本也没见过自定义 DSL。
- 状态用自然语言描述，不用 `[TARGET_ENTITY: Face_89]` 这类自造标记。模型的 CAD 先验来自论坛和手册里的自然语言，自造格式等于丢掉先验。
- 不合法的指令在打分前就从候选表里剔除，由宿主软件的确定性规则判断，不交给模型。
- 延迟预算是拾取到候选就绪 100ms 以内，不追求 10ms。人一次选择动作本身约 200ms。
- 猜错必须零成本：候选框不抢焦点、不吞按键，鼠标移开或继续操作即销毁。命中率不是成立条件，这一条才是。
- 零样本模型只负责冷启动。每次采纳/忽略都记成带标签日志，攒够后做 LoRA 或在 embedding 上训练轻量重排序头。

- 第一版宿主是 Solid Edge（实机 2020）。拾取状态和指令执行走 Solid Edge COM，不经 SolidEdgeMCP 的 MCP 外壳：那是给 AI 建模用的，这里要的是事件和原生命令。

## 真机才知道的事

- Solid Edge 2020 的 COM 暴露 `Application.ApplicationEvents`、`ApplicationWindowEvents` 和 `Document.DocumentEvents`、`SelectSet`（2026-10-28 用 pywin32 读到；事件尚未实际挂接）。
- 完整指令表来自 `Environment.CommandCategories` → `CommandInfo`（Id、Caption、Tooltip、Description、BuiltIn），不是 `constant.tlb` 里的 `PartCommandConstants` 等枚举：后者只有菜单时代的 183 条零件命令，没有同步建模和功能区命令。2026-10-28 中文界面实测 39 个环境共 7490 行、925 个不同 Id；同步零件 DMPart 492 条，其中“主页”160 条。同一命令在一个环境里会出现在多个分类，按 (环境, Id) 去重。
- `Application.CommandEnabled(Id, 环境)` 在装配环境下逐条调用时 Solid Edge 进入未响应并占满一个核，连单次 `GetActiveObject` 都拿不到（2026-10-28）。原因未查明，在弄清之前不要批量调用它当掩码。
- 静态导出只说明“有哪些命令”，说不清“实际怎么触发、Id 怎么报”，切面以监听为准。2026-10-28 实测：`ApplicationEvents` 与 `DocumentEvents` 用 pywin32 取出来是裸 IUnknown，`WithEvents` 不能用，要拿 makepy 生成的 `DISEApplicationEvents`/`DISEDocumentEvents` 直接挂连接点；挂接后不会让 Solid Edge 卡死。
- 命令事件的形状（2026-10-28 DMPart 模拟鼠标实测）：空闲时一直处在选择工具 45000 里；任何操作都是“45000 after → X before → X after → 45000 before”。所以 X 的 before 就是一次操作，45000 不算操作。`StartCommand(10879)` 在无几何的空零件里不报事件，有几何时点功能区“倒圆”正常报 10879。
- 同步建模最核心的操作导出表里没有：拖方向盘主轴移动面报 10311（三张表都没有），选面按 Delete 报 40212（只在 `constant.tlb` 的 PartEditDelete 里）。候选指令表 = 导出表 + 监听补录，补录写在 `surface/observe.py` 的 `IMPLICIT`。
- 选择事件只反映命令外的预选。命令内部的拾取（如倒圆里点边）不触发 `SelectSetChanged`；右键会把同一选择集再报一次。`Type` 只分到大类，几何细节读 `item.Geometry.Type`（平面 igPlane、圆柱 igCylinder，都在 `constant.tlb` 的 `GNTTypePropertyConstants`）、`Geometry.Radius` 和 `Area`，倒圆面实测读出圆柱 R5。
- 草图区域被选中时 `Type` 也报 igFace、几何也是平面，和模型面分不开（状态栏能区分，显示“区域（草图 n）”）；还没找到区分它的属性。点孔会选中整个孔特征（`FeatureTypeConstants.igHoleFeatureObject` 462094722），不是孔面；孔命令完成时也会自动选中新孔，且这个选择事件早于孔命令的 after。
- 同步建模里同一个操作有多个入口但只报一个 Id：点草图区域的拉伸箭头报 10295，和功能区“拉伸”一样；方向盘移动面和缩短面都是 10311。命令失败（如拉伸弹“操作失败”）事件上看不出，照常 before/after。
- 面相关组 12 个图标里 9 个直接报命令（同心 10864、对称 10871、偏置 10862、对齐孔 10872、相等 10868、固定 10869、相切 10867、水平/竖直 10880、刚性 10870），另 3 个是下拉、不报事件。方向盘的旋转环没有摸出来：悬停原点只高亮，点主轴直接进 10311。
- 同步建模默认面优先，命令外在边上单击会选中相邻面，选不到边；选边要先进入需要边的命令。
- 选中面后的右键菜单只有剪切、复制、删除、切换构造等通用项，没有建模命令。光标旁的下一步候选正好补这个空。
- 本机统一推理服务（`127.0.0.1:11435`，qwen3.5:35b-a3b Q4_K_M，llama-server）已占满显存约 11.2/12.3GB，装不下第二个常驻模型。
- 该服务 `/completion` 只回生成 token 的 top_logprobs，不能对任意续写打分。可行做法是把指令表编号放进固定前缀，读一个字母 token 的分布；前缀命中缓存后，4 token 增量约 150ms，冷启动约 9s。裸提示下首 token 多为换行，提示格式还要调。
